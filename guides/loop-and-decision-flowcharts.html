Decisions split a path and can rejoin it

An if/else statement becomes a diamond with true and false paths. With the default labels, Yes means the condition is true and No means it is false. Follow the condition literally: for x < 0, Yes means negative, not simply “success.” You can change the printed labels in Settings without changing the underlying branch.

Branches often meet at the next shared statement. A return changes that: it exits the current function, so it must not lead to a statement that appears later in the source. An else-if chain is several decisions, not one diamond with arbitrarily many Yes paths.

For, while and do/while test at different times

A for loop normally has initialization, a condition, a body and an update. A while loop checks its condition before entering the body. A do/while loop enters the body first and checks its condition afterward. This difference explains why a supported do/while body can run once even when its trailing condition is false.

A loop’s return connector is not an extra execution step: it means the next test will happen again. Compact layout can reduce the space between nodes, but it must preserve that relationship. Changing the diagram to left-to-right moves the layout, not the order of operations.

Break, continue and return take different exits

In the example, continue skips the remaining body when i equals two; the for-loop update still happens before the next condition check. Break leaves the loop when i equals five. The final return exits main. Try tracing i = 1, 2 and 5 separately to see all three paths.

Inside nested structures, the destination depends on context. A break inside a switch exits that switch; a continue inside a switch nested in a loop continues the enclosing loop. Read the actual connector destination instead of assuming every jump goes to the bottom of the page.

Use the diagram as a reasoning aid

A control-flow diagram shows possible supported paths, not how often each one executes or whether the program terminates for all inputs. Literal true/false predicates may eliminate unreachable paths; other predicates are left as decisions. The generator does not run arbitrary code to guess a branch outcome. Use tests and a language runtime to investigate actual behavior.

Try it with real code

C
#include <stdio.h>
int main() {
    for (int i = 1; i <= 6; i++) {
        if (i == 2) {
            continue;
        }
        if (i == 5) {
            break;
        }
        printf("%d", i);
    }
    return 0;
}

Common questions

What shape represents a condition?

A diamond represents a decision. Follow the outgoing label and connector to the next node; the node’s position alone does not determine execution.

Why is a branch missing for while(0)?

A literal false condition never enters the body. The graph can omit that unreachable path without evaluating arbitrary source expressions.

Is a flowchart the same as a control-flow graph?

A control-flow graph models nodes and possible transitions. This tool renders its validated graph with familiar flowchart shapes, labels and routed arrows.
